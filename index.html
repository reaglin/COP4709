  • Module 3

    Module 1 (Week 1) - Review

    This module introduces the four-tier Database Skill Level Framework (L1 Foundational through L4 Expert/Architect) and the skills-by-role matrix covering seven career paths — DBA, database developer, data analyst, BI developer, data engineer, data scientist, and database architect — so you can audit your own competencies and plan certification and portfolio work. Alongside this roadmap, you install SQL Server Developer Edition and SQL Server Management Studio and build a working database, creating tables with primary and foreign keys and implementing both 1:N relationships and M:N relationships through join tables. Working from a supplied data dictionary (class advising, sports statistics, or music) or your own design, you will produce a reusable DDL script and an ERD using the SSMS diagram tool.

    11 items
  • Module 4

    Module 2 (Week 2) - ETL and Query

    This module takes on ETL/ELT in practice: downloading public datasets from Data.gov and the College Scorecard, using Excel to inspect and clean XML and CSV flat files by resolving blanks and placeholder values, converting formulas to static values, and trimming to the columns you need, then loading the result into a SQL Server table with SQL Server's free import and integration tools. Students then query the imported data — ranking institutions on the cumulative loan debt fields (CUML_DEBT_P10 through P90) with WHERE, ORDER BY, and row-limiting clauses, excluding zero values and small sample sizes, and appending Daytona State College for comparison. The work is delivered as a professional database results report that documents the data source and import process, shows the SQL used, and presents query output as formatted tables with interpretation.

    5 items
  • Module 5

    Module 3 (Week 3) - Stored Procedures

    This module covers writing T-SQL INSERT stored procedures for schemas with foreign key dependencies: declaring IDENTITY(seed, increment) columns, retrieving generated keys with SCOPE_IDENTITY(), @@IDENTITY, IDENT_CURRENT() or the OUTPUT clause, returning those keys through OUTPUT parameters, and using find-or-create logic for lookup parents such as artists or menu groups. Students assign dependency levels from foreign key constraints to derive a correct parent-to-child insert order, wrap multi-table inserts in BEGIN TRY/BEGIN TRANSACTION blocks with SET XACT_ABORT ON and @@TRANCOUNT checks, and handle failures with RAISERROR, THROW, and a reusable usp_LogError procedure writing to an ErrorLog table. The module also introduces user-defined table types and READONLY table-valued parameters for batch inserts, and compares the stored procedure approach with Entity Framework and ADO.NET alternatives.

    5 items
  • Module 6

    Module 4 (Week 4) - Stored Procedures 2

    This module covers user-defined functions in T-SQL: scalar functions, inline table-valued functions, and multi-statement table-valued functions, including their syntax, return types, the read-only rule, determinism and SCHEMABINDING, and how functions differ from stored procedures in DML, transaction, and TRY...CATCH support. Students write scalar functions for logic such as age calculation, tiered discounts, lookups with NULL handling, and string formatting, build parameterized table-valued functions over filtered and joined tables, and invoke them in SELECT, WHERE, ORDER BY, GROUP BY, CROSS APPLY, and OUTER APPLY. In the assignment, students create a table-valued function returning the menu items for a given menu ID and a scalar function returning a menu item description, then combine them in a working query, while also evaluating scalar UDF performance pitfalls and alternatives like inline TVFs, views, computed columns, and CTEs.

    5 items
  • Module 7

    Module 5 (Week 5) - Transactions

    This module covers database transactions and the ACID properties, using the bank transfer problem to show why atomicity, consistency, isolation, and durability matter, and compares how SQL Server, PostgreSQL, MySQL/InnoDB, Oracle, and NoSQL systems implement those guarantees under the CAP theorem. Students work with T-SQL transaction control — BEGIN/COMMIT/ROLLBACK, SAVE TRANSACTION, @@TRANCOUNT, SET XACT_ABORT ON, and TRY...CATCH rollback patterns — and distinguish the READ UNCOMMITTED through SERIALIZABLE and SNAPSHOT isolation levels by the dirty, non-repeatable, and phantom reads each prevents, along with lock types, granularity, and deadlock handling. By the end, students write a validation-first transactional stored procedure that transfers funds between accounts in a user-credit database, log transaction attempts, and judge when two-phase commit with MS-DTC or the Saga pattern with compensating transactions fits a distributed scenario.

    6 items
  • Module 8

    Module 6 (Week 6) - Cursors and Iteration

    This module covers database cursors and row-by-row (RBAR) processing in T-SQL: the full DECLARE, OPEN, FETCH, CLOSE, and DEALLOCATE lifecycle, looping with @@FETCH_STATUS, and the declaration options for scope (LOCAL/GLOBAL), scrollability (FORWARD_ONLY/SCROLL), type (STATIC, KEYSET, DYNAMIC, FAST_FORWARD), and concurrency (READ_ONLY, SCROLL_LOCKS, OPTIMISTIC), along with cursor syntax in Oracle PL/SQL, MySQL, and PostgreSQL. Students build cursor-based stored procedures with parameterized SELECT statements, per-row transaction control, and TRY-CATCH cleanup using CURSOR_STATUS, and complete an assignment writing sp_DisplayCollege, which iterates over colleges matching a partial name and reports each institution's values against plain and enrollment-weighted averages. Students also learn to weigh cursors against set-based alternatives — window functions for running totals, JOINs for cross-table updates, and batch processing for large datasets — and to apply a decision tree and pre-production checklist for judging when row-by-row work is genuinely warranted.

    3 items
  • Module 9

    Module 7 (Week 7) - Reporting

    This module turns query results into delivered reports, distinguishing operational, analytical, tactical, and strategic report types and weighing SSRS, Power BI, Crystal Reports, Tableau, and Jaspersoft on cost, learning curve, and fit before settling on SSRS Report Builder as the working tool. Students install Report Builder, connect a data source, build a dataset, bind fields to a table, format headers and numbers, add totals, and save an .rdl file, then extend it with matrix (crosstab) layouts, charts, cascading parameters, drill-through and drill-down visibility toggles, interactive sorting, and Visual Basic expressions. Using the US Aid database, they produce a matrix report of fiscal year by continent summing financial aid, troubleshoot expression, parameter, and deployment errors, and check finished reports against query performance, caching, number formatting, naming, and security standards.

    6 items
  • Module 10

    Module 8 (Week 8) - Lookup Tables

    This module covers lookup (reference/code) tables: their structure of primary key, value, and optional description, sort order, and active flags; criteria for deciding when a column warrants a lookup table versus a CHECK constraint; and design practices including surrogate versus natural keys, foreign key enforcement, soft deletes, indexing, and pitfalls such as hard-coding lookup IDs or breaking historical data. Students compare a single-table-per-field design with the two-table Categories/Codes architecture, build it in SQL Server with foreign keys, a CatCodes view, stored procedures that populate lookup values, and a scalar function that decodes codes. Working with coded Census Bureau PUMS microdata (fields such as ACR) and its data dictionary, students import raw coded records and produce grouped counts and cross-tabulations of two coded variables by joining to their lookup structures.

    6 items
  • Module 11

    Module 9 (Week 9) - Aggregation and Functions

    This module covers SQL aggregation: COUNT(*), COUNT(column), and COUNT(DISTINCT) and how NULLs and duplicates change their results, plus SUM, AVG, MIN, and MAX applied to numeric, date, and string columns of a sample bookstore orders table. Students work with AS aliases, GROUP BY on single columns, multiple columns, and date expressions, the rule that every selected column must be grouped or aggregated, and the choice between WHERE and HAVING as explained by SQL's six-step logical execution order; vendor-specific features such as GROUP_CONCAT, STRING_AGG, STDDEV, VARIANCE, and WITH ROLLUP are compared across Oracle, SQL Server, MySQL, PostgreSQL, and Db2. The assignment applies these tools to a US government food database, writing a stored procedure that splits foods into quartiles by fat-to-energy ratio and ranks the top and bottom ten by sugar and vitamin content.

    4 items
  • Module 12

    Module 10 (Week 10) - Full Text Indexing

    This module covers full-text indexing in SQL Server: how the full-text engine's word breaker, stopword filtering, stemming, and thesaurus expansion build an inverted index, why `LIKE '%term%'` forces a full scan, and how to create a full-text catalog and index with a unique key, language, and change-tracking options. Students write CONTAINS queries using exact phrases, AND/OR/AND NOT logic, prefix wildcards, FORMSOF, and NEAR proximity, compare them to FREETEXT for precision versus recall, and rank results with CONTAINSTABLE and FREETEXTTABLE using top_n_by_rank and rank thresholds, while managing custom stoplists and the XML thesaurus. In the assignment they build a full-text index on menu item descriptions and return items matching two search terms grouped by menu group, then contrast SQL Server's syntax with Oracle Text, MySQL MATCH...AGAINST, and other platforms' equivalents to decide when full-text, a B-Tree index, or a dedicated search engine is the right tool.

    3 items
  • Module 13

    Module 11 (Week 11) - Performance

    This module turns to SQL Server query performance: measuring logical and physical reads with SET STATISTICS IO and TIME to establish a pre-tuning baseline, querying Dynamic Management Views and Query Store for expensive queries, wait statistics, index usage and file I/O latency, and reading execution plans to distinguish index seeks, scans, key lookups and join operators. Students build clustered, non-clustered, covering (INCLUDE), filtered and columnstore indexes, weigh the read/write trade-off along with fragmentation, REORGANIZE versus REBUILD and statistics upkeep, and rewrite queries for SARGability while avoiding SELECT *, implicit conversions and poor EXISTS/IN/JOIN choices. The assignment applies this to the housing database with Category and Code lookup tables, profiling the Assignment 8 aggregation query, selecting and justifying an optimization — indexing, denormalization, summary tables or indexed views — and reporting pre- and post-optimization timings.

    4 items
  • Module 14

    Module 12 (Week 12) - Security

    This module covers database security as a layered discipline: the seven defence-in-depth layers (network, OS, authentication, authorization, data, audit, application), least-privilege design with role-based GRANT/DENY, Row-Level Security and Dynamic Data Masking, encryption through Transparent Data Encryption, column-level and Always Encrypted, TLS connections and certificate/key backup, plus SQL Server Audit specifications, failed-login alerting, surface area reduction, port and browser service restrictions, and post-incident forensics using volatile session state, the transaction log and audit timelines. Students write a two-part Hacker/Defender report that plans and demonstrates a SQL injection attack to extract user credentials, then documents the parameterized queries, input validation and backdoor hardening used to defend against it, with screen captures of both. They will also audit a database environment against a hardening checklist and argue a prioritised remediation order, and debate in discussion which database security risk is greatest and how to mitigate it.

    4 items
  • Module 15

    Module 13 (Week 13) - Advanced Query

    This module turns SQL into an analysis tool: it contrasts OLTP and OLAP uses of a relational database, walks the six-stage analysis pipeline, distinguishes dimensions from measures, and covers cleaning raw operational data with COALESCE, ROW_NUMBER for duplicate removal, CASE for category standardisation, and z-scores for outlier detection. Students write descriptive summaries, trend queries using LAG, running totals and rolling averages, and segmentation queries with RANK, DENSE_RANK and NTILE, then build rate-based KPIs protected by NULLIF and package them as date-parameterised cyclic reports in stored procedures. The assignment applies this to real Fall 2014 grade data, comparing short versus full terms and live, hybrid and online delivery using course GPA and course success score, with a discussion on advanced SQL puzzles covering join logic.

    3 items
  • Module 16

    Module 14 (Week 14) - NoSQL

    This module moves beyond the relational model to NoSQL, covering the four database families — document, key-value, column-family, and graph — and using MongoDB as the working example: documents, collections, BSON types, the _id field, and schema flexibility in mongosh. Students perform CRUD with insertOne, insertMany, find, findOne, projection, comparison and logical operators (including IN, AND, OR), updateOne/updateMany with update and array operators, upserts, and deleteOne/deleteMany; build aggregation pipelines with $match, $group, $project, $sort, $unwind, and $lookup; and create single-field, compound, unique, text, and TTL indexes, reading explain() output to tell a COLLSCAN from an IXSCAN. The assignment requires standing up a local or Atlas MongoDB instance, loading a dataset such as the restaurant collection, demonstrating IN/AND/OR queries, and documenting NoSQL's limitations and appropriate uses — including embedding versus referencing decisions, the 16MB document limit, and polyglot persistence.

    4 items
  • Module 17

    Module 15 (Week 15) - Summary

    The final week consolidates the full arc of the course — ETL and query design, stored procedures, transactions, cursors, reporting, lookup tables, aggregation and user-defined functions, full-text indexing, performance tuning, security, advanced query techniques, and NoSQL — into a single integrated picture of how these pieces fit together in a working database solution. Students review terminology and the models introduced in earlier weeks, map the connections between them, and then work a database case: framing the scenario, choosing which techniques apply, deciding under incomplete information, and defending a recommendation with evidence drawn from the case and the course material. A 45-question quiz bank supports preparation for the final assessment, and students close by auditing their performance against the course outcomes and drafting an action plan naming remaininggaps and concrete next steps for continued work with SQL and database design.

When I was leading large programming teams (I did this for over 15 years) I had some programming rules;

"Thou shalt only access the databases through stored procedures"

"Thou shalt have all stored procedures vetted by the database admin before implementation"

"Thou shalt use the naming convention for stored procedures specified in the coding conventions documentation" 

This last one had sample names for stored procedures like;

sp_insert_personnel (parameters)

sp_update_personnel( parameters) 

This was crucial to the functioning of large software teams (some projects had 30-40 programmers). 

The AI question this week is;

What are the best practices in passing data between the database and a web based client-server application?

The question for this post is based on the first rule (and a little bit of the follow on rules). Why would I only allow code to database access through stored procedures and also why would I require all stored procedures to be vetted by the DBA? This is not a trick question.
